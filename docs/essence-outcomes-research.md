# 多结果精华与展示占位核对

## 2026-09-18：普通数值属性的直接产物证据

[Diztoh 的头盔制作演示](https://www.youtube.com/watch?v=yegMdBTuEtY)上传于 2026-07-03。本次实际检查约 00:47–00:54 的画面，而非只采用自动转录。材料提示为 Greater Essence of the Infinite，展示范围 25–27、三属性之一及魔法升级稀有。使用前 Kamasan Tiara 为魔法，已有护盾点数前缀和稀有度后缀；使用后为稀有，新增白色智慧工艺行，数值 26、范围 25–27，显示 T4，其余两条保留。高级提示显示物等 81。

与当前固定 MIT 目录独立比对：基底标签为 `armour/default/helmet/int_armour`，对应 `Intelligence6` 的范围、后缀身份和 `Intelligence` 冲突组；其内部生成等级为 55。该内部标识是目录对应推断，不是视频显示的标识。上传日期不等于客户端构建号，也不构成国服文本验收。

这补上了高级数值精华的一条真实产物，但不能判定该纯护盾头盔是否也会获得力量或敏捷。尤其是目录中的 `helmet` 本身就允许普通智慧，不能由此证明精华越过普通资格。后续应优先寻找能区分两种假设的操作：在不具备普通敏捷／智慧资格的腰带上观察实际结果，或核对明确解释候选筛选的官方规则；重复收集纯护盾头盔获得智慧的例子不能解决该分歧。

本次不改变执行结果集、材料费用或项目规则版本。防御三档已由 v115 接入；下文 v88/v89 内容为历史审计基线。

核对日期：2026-09-16。最初审计基线为 v88；完美三属性已由 v89 接入，以下明确区分已实现与待核对规则。目标是补齐真实材料的结果分支，而不是把展示文字伪装成可生成词缀。

## 未解析映射的实际组成

逐条连接入库 `catalog.essences[].mods` 与 `catalog.modifiers[].id`，698 个类别映射中有 594 个直接对应，104 个未对应，集中在以下 8 个 ID：

| 展示标识 | 类别映射数 | 材料范围 |
| --- | ---: | --- |
| `EssenceDisplayDefences1`、`2`、`3` | 各 7，共 21 | 三档 Enhancement；七种防具类别 |
| `EssenceDisplayAttributes1`、`2`、`3` | 各 27，共 81 | 三档 Infinite；来源明确列出的 27 类装备 |
| `EssenceDisplayAttributes5` | 1 | Perfect Infinite；项链 |
| `EssenceGrantedPassive` | 1 | Delirium；胸甲 |

104 是“材料与类别关系”的数量，不是缺少 104 条独立词缀。前三类不能通过给占位 ID 人工补上 `CatalogMod` 就解决；最后一类还涉及授予天赋，不能与普通数值属性共用假定结果。

固定来源：`Essence.lua` SHA-256 为 `950219488fed20cc3ca1bad17953f577c4361c6b65e371ce9ae3f9cbbae95f74`，`ModItem.lua` 为 `774257f577f8cee8ac59d7848df4bc7a109d266a615eb97c2a2c08ecb6b47cf4`。二者均对应现有 MIT 提交，不更新游戏数据快照。

防御说明使用合并展示，并不证明单系防具会得到同时提高三项的实际属性。固定目录有七种不同冲突组，必须核对单系、双系、三系，以及锻造、法器和小圆盾的规则；不能选择第一条数值相符的记录。结界也不能因内部名称叫 Defences 而被加入效果。

普通 Infinite 的数值相符记录具有不同普通生成资格。例如目录中腰带可自然生成力量，而敏捷的默认资格不覆盖腰带。材料说明列出腰带，不独立证明三种属性均可越过普通资格；也不能反过来直接用普通池排除特殊制作结果。该问题与完美档项链的独有结果分开核对。

### 等级字段必须分开

公开页表格为 Required Level，固定目录为词缀生成等级。例如高级防御页列 43，而相符目录记录为 54；高级属性页列 44，对应目录记录为 55；完美属性页列 57，目录记录为 72。这不是已证明的版本冲突，更不是把制作物等门槛改成 43／44／57 的依据。材料掉落等级也是另一字段，不参与替换。

## 完美无限精华的结果依据

固定目录的三个实际记录均为后缀，名称同为 `of the Essence`，但 ID、冲突组和交易 stat hash 不同：

| 实际 ID | 冲突组 | stat hash |
| --- | --- | --- |
| `EssencePercentStrength1` | `PercentageStrength` | `734614379` |
| `EssencePercentDexterity1` | `PercentageDexterity` | `4139681126` |
| `EssencePercentIntelligence1` | `PercentageIntelligence` | `656461285` |

三者均为 7–10%、生成等级 72，普通资格默认关闭。接入必须由项链上的精确材料声明授权，不能开放到普通崇高池或其他类别。

[Carnarius 原视频](https://www.youtube.com/watch?v=QmyNWhUQ2Ko)于 2026-06-07 发布，标题注明 0.5；转录在第一种方法中明确讨论得到敏捷或智慧后的处理，16:12 开始第二种方法，描述对两条已有后缀的项链使用前缀结晶预兆，再施加精华而未得到所求力量。本轮没有逐帧读取，因此这是作者操作讲解的交叉证据，不标为本项目真机验收。

材料公开说明、三个独立目录记录和作者讲解共同支持为普通项链提供三种手选结果。作者提到的三分之一命中率没有独立采样或权重证明；后续只展示候选与风险，不写等概率或期望费用。讲解中的催化倍率、复合预兆及价格同样不自动进入本项目规则。

同提交 `ItemsTab.lua:3430` 附近只按材料映射 ID 查已有／独有词缀，找到可描述记录才加入列表。它没有补齐本次展示占位，因此不能以 PoB 列表缺失推断材料不可用，也不能拿该代码推导完整候选集合。

## 接入边界与全链验收

接入前的单结果假设同时存在于 `inspectEssences`、`prepareEssenceCraft`、实际操作、目标建议和网页选择。v89 新增统一的“材料声明 → 实际结果集合”解析；调用方复用它，不能在界面与核心各写一份特判。

1. 先接入已有充分结果依据的完美档三分支。操作增加可选的结果 ID；多结果材料必须明确选择，单结果旧操作保持原样。结果 ID 必须属于当前材料和基底，不能借新增字段指定任意属性。
2. 保存、起点导入、目标、未执行指引及全部未来步骤使用新规则版本。原 v88 及更早项目即使游标尚未到达该动作，也拒绝夹带新能力；来源指纹覆盖材料及实际属性，不把新增结果视为普通词缀。
3. 目标建议遍历全部结果，条件动作按材料预检后由用户选择本次结果。不能仅检查第一种结果而误判整个材料不可用；已有词缀冲突、破裂保护、工艺容量与结晶预兆仍逐个结果校验。
4. 网页查询和选择保留材料名称、独立结果文字及数值范围，避免重复 React key 或同名按钮选错分支；切换结果清空不再合法的移除选择。整次动作只计一份材料，预兆另外计费。
5. 验证三种结果的中文导入、现有后续制作、目标与路线、预览取消、撤销重做、文件／本机／收藏恢复及计划导出。旧单结果精华须保持兼容，所有未执行的新能力声明也检查版本。

这不是将范围缩为一件项链工具：普通三档 Infinite、防御三档及 Delirium 仍保留在完整目标内。它们需要分别确认越过普通生成资格、按基底选择防御家族和授予天赋的身份，随后复用结果集合入口；不以容易通过现有测试的虚假单结果替代它们。

CoE 的公开更新说明继续用于对照工艺标记、精华错误反馈与条件流程。本轮不读取其代码或数据。来源许可与用途见 [登记表](data-sources.md)。

## 防御精华的类别与家族审计（v89 后续）

2026-09-16 继续以同一固定目录核对，未调整执行规则。

### 旧错误报告已有官方修复

[2025-09-01 至 09-04 的原始报告](https://www.pathofexile.com/forum/view-thread/3835288)记载 Tasalian Focus 的深渊精华以及 Cultist／Druidic Focus 的防御精华因基底类别而失败。[GGG 0.3.0c 原公告](https://www.pathofexile.com/forum/view-thread/3851277)于 2025-09-11 明确修复防具精华不能用于法器和小圆盾的问题。因此不能继续用该历史报告排除这两类装备；它也没有说明实际生成哪一条防御词缀。

[SaVeQ 的 0.5 召唤头盔原视频](https://www.youtube.com/watch?v=ppH5TmZTsCQ)讲解：以固定闪避值起手时可以使用高级防御精华取得百分比闪避，但起手已有百分比闪避时不能使用。转录将材料误写为 enchantment，语境明确讨论该防御效果；这是单系闪避及冲突方向的辅助证据，没有逐帧确认结果，不能推导混合防御或结界结果。

搜索找到的 Fubgun 头盔转述页仍将三项防御合并展示；未找到可核对的原视频结果帧。另一个标题注明 0.5 的 Belton 视频发布于 2026-05-19，正文谈下一次开服，不能仅凭标题认定画面来自当前版本。后续须核对录制版本与实际操作，不能将其他工具的目标列表当作真机证据。

### 固定目录的完整候选矩阵

按三档材料声明的七个类别遍历所有基底，并按 `eligibility` 的**首个匹配标签**判断普通生成资格（不是随机权重）。三个数值范围各找到七个已有防御家族：

| 材料档位 | 范围 | 家族 ID 档号 | 生成等级 |
| --- | --- | --- | --- |
| 次级 | 27–42% | 2 | 16 |
| 普通 | 56–67% | 4 | 46 |
| 高级 | 68–79% | 5 | 54 |

七个家族分别为护甲、闪避、能量护盾及其三种双系组合、三系组合。高级闪避＋能量护盾的 ID 是 `LocalIncreasedEvasionAndEnergyShield5_`，末尾下划线是实际身份的一部分，不能通过统一拼接档号生成 ID。

七类共 1,273 个目录基底，其中 1,269 个恰好匹配一个上述普通家族，没有多匹配；4 个没有匹配：

| 材料类别 | 恰好一个候选 | 无候选 |
| --- | ---: | ---: |
| Body Armour | 368 | 0 |
| Gloves | 201 | 0 |
| Boots | 190 | 1 |
| Buckler | 52 | 0 |
| Shield | 148 | 1 |
| Helmet | 259 | 2 |
| Focus | 51 | 0 |

无候选基底为 Golden Caligae、Golden Flame、Golden Visage、Golden Wreath，均有 `demigods`／`not_for_sale` 标签；它们在目录的 `hidden` 为 false，不能只检查 hidden 就假定有可制作结果。本计数包含目录里的锻造等基底，不等于已证明 1,269 个基底均可执行防御精华。

这是实现候选选择的可行性证据，仍缺“材料结果应按此家族选择”的完整核对，尤其是混合防御与新增结界。不从当前面板数值反推家族：品质、固有属性及镶嵌可能改变面板，但不会自动改变材料声明。

### 对下一步实现的约束

- 统一结果入口应按精确材料与类别声明、明确家族身份解析；不能将展示占位补成虚构属性，也不能简单选择第一条数值相符记录。
- 新版门禁应扫描三种防御精华的实际动作和未执行指引。普通防御词缀 ID 早已合法，不可因为新精华使用同一 ID 而拒绝全部旧装备、旧目标或普通通货历史。
- 覆盖七个家族与三个档位、法器／小圆盾、四个无候选基底、锻造结界、同组冲突、物等门槛、工艺容量、导入回读及完整未来。材料类别已确认的部分不再重复取证，后续集中核对家族与结界交互。
- 普通属性精华三档的候选分别为 Strength／Dexterity／Intelligence 的 2、4、6 档，生成等级 11、33、55；跨普通资格的结果仍未确认。本轮搜索主要返回重复物品说明或旧规则，不据其开放腰带敏捷／智慧。
