# 混沌石无新增候选的边界核对

核对日期：2026-09-18。此记录用于后续取证，不改变当前执行规则。

## 线索与当前实现

[CoE 公开更新日志](https://beta.craftofexile.com/changelog)在2026-09-17记录修复 PoE2 混沌石在无法添加词缀时不能成功的问题。它证明该工具调整了模拟行为，但未给出装备、材料档次、预兆、游戏版本或游戏实操，因此尚不能作为本仓库开放新结果的唯一依据。本次只阅读公开说明，没有获取实现、候选表或权重。

本仓库 `rehearsal.ts` 的 `prepareCraftOperation` 在确定移除对象后，对混沌石设定新增数量为1；若移除后的 `craftCandidates` 为空，则返回失败。`applyCraftOperation` 同样要求结果数量与准备阶段一致。因此该线索对应的是核心状态转换边界，不是单独修改界面按钮即可解决。

现有候选资格还包含最低词缀等级的家族最高档例外。不能只按“全部普通词缀低于完美混沌石门槛”构造结论；必须检查完整候选函数。目录为空也可能来自来源缺失或尚未支持的交互，不能自动当作游戏没有合法候选。

## 本次搜索结果与下一步

Exa 与网页搜索的“无新增”“只移除”等查询仍主要返回通用的一移一加说明、商业攻略和 PoE1 讨论，没有取得可独立核对的 PoE2 操作记录。谵妄精华查询也未补齐材料专属候选声明，相关缺口仍见 `delirium-passive-research.md`。未将搜索未命中解释为该机制不存在。

下一项有效证据应包含：操作前高级装备文本、具体混沌石档次与预兆、被移除属性及操作后文本、实际消耗，以及可确认的客户端版本。随后用相同起点核对本仓库的候选和容量计算，区分真实无候选与数据缺失。

若确认存在只移除的合法结果，需要一起覆盖材料与预兆消费、词缀身份、撤销及完整未来、目标路线和条件阶段回放，并为旧项目保留原语义。取得证据前，不将空候选静默改为成功，也不以同行工具结果代替游戏实测。
