# 扩展实站验收的自造流程

`two-step-lightning-route.json` 是本项目通过新版CoE公开界面自行配置、用原生Export Simulation导出的流程，2026-09-25在扩展0.1.24下执行。文件只增加缩进，保留原导出字段；不含用户私人物品，也不是原站规则库或数据文件。上游格式和动作身份可能变化，不把它当作稳定API。

## 流程与核对点

- 起始：普通符文法器、物等100，无词缀。
- Step 1：普通蜕变石；闪电抗性条件78满足则结束，结束优先级0；否则通过优先级1的连线进入Step 2。
- Step 2：普通增幅石；同一条件满足则结束，否则重新开始。
- 运行：fixed／items／10，保存结果。

0.1.27 已独立验证重新导入：流程模拟 → 新建模拟流程 → 导入一个流程 → 粘贴该 JSON → 继续。再用“导出模拟流程”取得 JSON，与本文件解析后逐字段完全一致。不要使用“载入 → 全部导入”，后者要求批量导出数据，会拒绝单个流程并给出中文指引。复测也可按上述动作重建；选择条件后先检查编辑状态，应用后再次核对导出中的requirements，不能只看界面文字。随机结果不会每次相同，完整证据和未解决问题见上级compatibility.md。

样本中的两个随机步骤ID只表示连线关系，不关联个人身份；action里的legacy标记是原站导出格式，不表示扩展使用旧域名。

## 两个条件组的调查样本

`two-group-resistance-route.json`由原生UI在两步样本基础上配置并导出：第一步结束要求含or(78,77)及not(80)，matches均为null。它是待继续分析的调查样本，不是已经验证符合预期逻辑的制作方案。实测运行10件全部通过第二步结束；第一步未直接结束，原因与数字匹配控件事件仍待核对，见compatibility.md的两条件组记录。

`two-group-match-one-route.json`是上述样本在无扩展英文原站以真实键盘把第一组匹配数量设为1后的原生导出，保留字符串`"1"`。最终0.1.52中文包从null样本重复键盘编辑，导出逐字一致；两边运行均完成10件且第一步可直接结束。它验证这一配置链，不代表所有分组逻辑、阈值或循环均已验收。

## 显式回边调查样本

`explicit-backedge-no-start.json`为原生UI生成的Step1→Step2→Step1无动作回边，没有显式起点，会触发起点选择错误。`explicit-backedge-property.json`是最终0.1.53包选择Step1起点并添加能量护盾属性后的原生导出；属性tier仍为null，不能将它当作指定阈值的模板。

这是调查样本，不是可完成的制作方案。已有实测表明无动作回边不会自动结束，需要原生停止按钮；不要当作自动化批量执行样本。全部字段保留原生导出，仅格式化JSON。循环运行、手动停止、启停导出以及数值未保存的边界见compatibility.md。


`silk-slippers-zh-CN.txt`为自造稀有丝绸便鞋高级文本：品质20%、一个空孔、T3护盾40和T6闪电抗性18。`silk-slippers-native.json`是无扩展英文基线的原生导出，仅格式化；0.1.57最终ZIP中文转换后的原生导出与该基线逐字一致。不是用户私人物品，也不包含站点规则库。


`silk-slippers-speed-zh-CN.txt`在自造便鞋上加入无括号范围的20%移动速度T4前缀；`silk-slippers-speed-native.json`为对应英文样本的原生Export，仅格式化。0.1.58最终ZIP完成中文预览与原站导入，导出逐字一致。


## 翠玉项链导入样本

`jade-amulet-zh-CN.txt`是自造稀有翠玉项链：敏捷固有属性12(10-15)、敏捷后缀24(21-24)T4、闪电抗性18(16-20)T6。`jade-amulet-native.json`及带`normal`、`magic`后缀的两份JSON分别为无扩展英文原站的稀有、普通、魔法导出，仅格式化；普通只保留固有属性，魔法另含敏捷后缀。0.1.62最终ZIP完成三种中文结构的导入，原始导出均与对应英文基线逐字一致。不是用户私人物品，不含站点规则数据库。


## 渎灵条件数值调查样本

`desecrated-prefix-null-tier-route.json`来自自造两步流程的原生导出，第一步结束条件加入`special:veiled-prefix`。0.1.68最终包中，新称“渎灵前缀”、旧称“亵渎前缀”和直接英文Desecrated Prefix查询均对应同一原生选项。旧称和英文分别选中、真实键盘输入1、应用后，完整导出除lastModified外一致；但该条件tier仍为null。本样本仅供继续调查，不是已验证阈值有效的制作路线，未运行其条件分支。


`settled-condition-tiers-route.json`为上述调查的0.1.69后续成功样本。使用最终扩展包，真实键盘输入并失焦后等待一秒再应用，第一步结束条件的普通闪电抗性tier为字符串"2"、渎灵前缀tier为字符串"1"，重新打开编辑器仍保留。它证明这两个字段保存与导出，不代表路线已运行或语义判断已验收；null样本保留为快速操作下的历史证据，不能再据其断言扩展会无条件丢失数值。


## 能量护盾阈值分支对照

`energy-shield-41-branch-route.json`与`energy-shield-43-branch-route.json`为自造确定性两步流程的原生导出，除阈值和lastModified外完全一致。起始普通符文法器能量护盾42，两步action均null；第一步按能量护盾属性判断是否结束，不满足则进入第二步直接结束。固定运行10件。

最终0.1.69包与无扩展英文原站均实际运行：阈值41的10件全部在Step 1结束、共10步骤；阈值43的10件全部在Step 2结束、共20步骤。运行次数均显示11、完成10、成功率90.9%，原站计数原样保留。样本用于验证属性阈值与分支，不含制作动作，不能作为制作成本或随机概率的依据。


## 红玉戒指导入样本

`ruby-ring-{normal,magic,rare}-zh-CN.txt`为三种自造高级文本，均含25(20-30)%火抗基底，魔法及稀有另含18(16-20)% T6普通火抗后缀。对应`-native.json`为无扩展英文原生导出，仅格式化；0.1.72最终ZIP的中文转换与对应英文原始导出逐字一致。基底身份FourRing3，固有值25与FireResist3后缀18分组保留。不是用户私人物品，不含原站规则库。


`ruby-ring-transmutation-native.json`为0.1.75最终包完整链验收中的一次原生蜕变石结果：从上述normal中文样本导入，实际操作生成FireResist2=11的魔法戒指，固有火抗仍25。撤销后的原始JSON逐字等于导入基线，关闭扩展后的Export也逐字一致。本文件只保留该次随机结果用于检查结构，不保证重复制作命中同一词缀，也不是权重证据。


## 首饰生命前缀组合

`{ruby-ring,sapphire-ring,jade-amulet}-life-{magic,rare}-zh-CN.txt`是六份自造高级文本：生命50(40-59)，戒指T5、项链T6；另含原有火抗、冰抗或敏捷后缀。对应`-native.json`来自无扩展英文原站导出，仅格式化。0.1.76最终ZIP逐一转换中文并导入，六份原始导出均与英文基线逐字一致，IncreasedLife4值50与后缀独立保留。不是用户私人物品，不含制作规则库。


## 首饰元素抗性组合

`{ruby-ring,sapphire-ring,jade-amulet}-elemental-{magic,rare}-zh-CN.txt`为六份自造文本。三种稀有首饰均含50(40-59)生命前缀和三条18(16-20)%元素抗性后缀；魔法红玉／蓝玉／翠玉分别含冰霜／闪电／火焰抗性及生命。对应`-native.json`来自无扩展英文原站导出，仅格式化。0.1.80最终ZIP逐一转换中文，六份原始导出与英文基线逐字一致。不是用户真实物品，不含规则或权重数据。


## 自定义价格设置往返

`custom-exalted-price-settings.json`来自隔离英文原站的原生设置导出，仅格式化：在leagueSoftcore把崇高石的显示价格自设为12.3456，原站保存为内部换算值1.5999897599999997。0.1.81中文编辑、重载导出与英文对照逐字一致；0.1.82最终包通过“导入设置→继续→替换确认→继续→自动重载→导出设置”再次逐字一致。样本只用于配置结构和身份验证，显示换算依赖原站当时价格数据；不是用户配置或当前行情表，导入会替换测试浏览器的原站设置。


`custom-price-leagues-four.json`与`custom-price-leagues-cleared.json`为四赛区自造价格调查的英文原生导出，仅格式化；后者只清空leagueHardcore的崇高石键。0.1.82中文路径在编辑、清空、重载三阶段均与英文原始导出逐字一致。但standardHardcore在原站导出为null、重载为空，样本保留该异常，不是四赛区完整恢复模板；复现范围见upstream-issues.md。

## 同时成立路线的优先级样本（0.1.86）

`priority-step2-first-route.json`从energy-shield-41-branch-route经公开UI上移Step 2路线后原生导出。起始护盾42，结束条件至少41和直接连线同时成立，连线priority=1、结束priority=2；无随机制作动作。英文与中文各运行10件均经第二步结束、执行20步，全部路线统计一致。把原有结束路线排首位的基准运行10步。文件仅格式化，不重编号原生优先级。快捷操作首轮未成功及保存时间字段差异见compatibility.md，不把本样本当作所有流程引擎行为的保证。
