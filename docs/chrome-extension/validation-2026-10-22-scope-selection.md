# 0.10.1 章节范围与空态整改验收（2026-10-22）

本轮按用户批准的评审建议修复章节范围、零选择状态和重名章节语境。沿用尚未发布的 0.10.1 本地候选，没有提交、推送、部署或更新商店草稿。

## 最终行为

- 保存服务并返回时，正文来源、块内容/结构和阶段身份一致则保留原章节子集与用户选择的阶段，不再恢复全选。提取时间和新生成的快照编号不影响恢复。
- 正文、结构、地址或读取范围变化，或旧会话已经失效时，保持未选择并提示在“翻译范围”中重新选择章节。这里采用保守恢复，不按可能复用的段落编号或相似文字猜测。显式“重新读取”仍按原设计重置范围。
- 零选择显示“先选择章节／尚未选择正文”，禁用开始操作。重新选择后恢复对应的开始、继续或完成状态，并清除旧的重新选择提示。
- 重名章节在可见标签中补充父章节路径；普通章节保持短标题。沿用原有双语顺序，不增加“返回目录”。

Chrome 149，隔离配置，以实际扩展页面的 320×900、420×900 视口模拟侧栏。加载由最终 ZIP 解出的副本，使用 52 段本机合成文章、虚构 Key 和本地兼容接口；真实外部模型请求为 0。完成一轮检查及一次修正后的确认。

| 流程 | 实测结果 |
|---|---|
| 全不选 | 按钮显示“先选择章节”且禁用，状态“尚未选择正文”，选中数 0 |
| 仅选一章后保存服务 | 保存后仍仅有 Starting the campaign 的 b1/b2/b3，状态 0/3，焦点回设置入口 |
| 开始翻译 | 请求只含 b1/b2/b3，不含排除章节正文或标题语境，最终 3/3 |
| 零选择后保存 | 仍为零选择，没有模型请求 |
| 设置期间原文改变 | 回阅读后零选择，显示重新选择提示；没有自动发送 |

未覆盖 Windows 日常 Chrome、真实 sidePanel 容器行为、读屏软件、真实网站 DOM 漂移或外部 API 故障；不扩大兼容性声明。此前整段语义质量未通过的结论保持，参见 [通用阅读契约](guide-reading.md)。
