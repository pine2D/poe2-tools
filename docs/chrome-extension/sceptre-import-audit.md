# 罪孽权杖导入核对

日期：2026-09-25。原站为 https://beta.craftofexile.com/?game=poe2 的 English 模式，无扩展。结论限定以下样本，不推导其他权杖或游戏规则。

## 已证实的行为

用户权杖的基底为 Rattling Sceptre。国服词典已覆盖精魂、技能整行、四组显式词缀，转换器可以保留当前等级12和最高等级13、复合后缀及固定数值。没有翻译缺口需要借助繁简互转。

以用户结构制作测试名称的英文样本：物等53、精魂100、需求等级24，技能为`Grants Skill: Level 12 Skeletal Warrior Minion (Max Level 13)`。保留一前缀、三后缀；前后缀名称统一用Test，标签用英文。原站无导入错误，结果如下：

| 输入 | 原生导出中的词缀身份 | 数值 |
| --- | --- | --- |
| 在场友军伤害54(45-54)% | NearbyAlliesAllDamage3 | [54] |
| 所有召唤生物技能等级+1 | GlobalMinionSpellSkillGemLevelWeapon1 | [1] |
| 魔力再生20(18-22)%＋照亮范围15% | LightRadiusAndManaRegeneration3 | [15,20] |
| 在场友军暴击15(15-19)% | NearbyAlliesCriticalStrikeChance2 | [15] |

复合组在原站按照亮范围、魔力再生的顺序保存；这是同一词缀的两个值，不是拆分成两条后缀。原站可见等阶与输入的6、4、1、5一致，精魂显示100。

问题在于技能：原站显示`Grants Skill: Level 13 Skeletal Warrior`，并非输入的12。只把输入当前等级改成1，其余字段不变再次导入，仍显示13。两次原生Export输出均463字符且逐字一致，`ns=null`、`p={}`，没有独立保存输入当前等级。读取方法为临时测试textarea复制唯一标记、点击原生Export、下一次调用再正常Ctrl+V；未调用站点内部函数或覆盖剪贴板API。

完整原生导出保存为`fixtures/rattling-sceptre-native.json`，仅格式化JSON。基底身份为`Metadata/Items/Weapons/OneHandWeapons/Sceptres/FourSceptre1`。中文回归样本为`fixtures/rattling-sceptre-zh-CN.txt`，只将用户原装备名称替换为测试名称。它不是游戏客户端重新实测样本。

原站Edit菜单可见质量、物等、插槽、腐化、镜像及自动保存开关，未发现独立技能等级入口。这是已查看菜单的观察，不证明所有页面都不存在设置。

## 对扩展的影响

- 当前保留完整中英预览与技能区块诊断，不将这件权杖标为可无损提交。
- 不能为了通过资格检查把当前等级改成13、删除技能行、给固定数值虚构范围，或拆分复合后缀。
- 不把原站自动计算解释为游戏中“12必然应为13”；游戏角色等级、装备技能上限及加等级词缀的交互不在本轮研究范围。
- 后续接入权杖需明确原站技能等级的能力边界。若要提供允许差异的提交模式，必须单独设计可见差异说明与选择流程，不能沿用现有“身份和值已保留”的就绪状态。

## 验证与剩余工作

新增两项回归使用当前入库国服词典，分别断言12／1和最高等级13原样翻译、精魂保留、技能结构继续阻止提交；以及复合后缀仍为同一组，固定1与15不虚构范围。核心／扩展21文件139项测试通过；没有修改运行时代码或升级0.1.50包。

此证据不等于权杖已支持，也不等于复制装备的所有语义都能由原站保留。完整扩展仍缺材料搜索入口、真实输入法、多层条件与显式回边、完整语言／页面矩阵及CI远端门禁；可继续这些独立施工，不等待权杖问题解决。
