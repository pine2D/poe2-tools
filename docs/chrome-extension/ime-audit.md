# 真实拼音输入验收

日期：2026-09-25。扩展0.1.58最终ZIP；Chrome for Testing 151.0.0.0，有界面X11；Fcitx5 5.1.7拼音。页面为新版CoE的英文PoE2 Data物品搜索。

本记录证明Linux Fcitx5这一组合的两条交互链，不证明Windows微软拼音、其他输入法、制作基底框、词缀框或条件编辑框已完成IME验收。

## 环境与方法

- 使用本机已有Fcitx5、拼音模块、GTK输入模块、Xvfb和libXtst；没有安装新软件或升级全局工具。
- 在临时目录放置独立XDG配置、数据、缓存与运行目录，通过独立D-Bus和Xvfb启动浏览器与输入法。配置参考[Fcitx官方设置说明](https://fcitx-im.org/wiki/Setup_Fcitx_5)，只对测试进程设置环境变量，不修改用户的配置。
- 首次Fcitx会话受继承的Wayland环境影响退出，该次不计入验收。终止确认后，移除测试进程的Wayland变量并关闭其Wayland模块，使用X11与keep选项成功建立会话。
- 浏览器自动化负责定位输入框和读取结果；拼音字符、空格、方向键、回车与取消键由libXtst向独立X显示发送系统按键，交给真实Fcitx5处理。没有用fill写入中文，没有调用dispatchEvent制造composition事件。
- 在页面window捕获阶段只记录自造查询的事件类型、data、key、isTrusted与输入框值，不读取或改写CoE内部业务对象。浏览器命令使用与启动时相同的XDG运行目录，避免连接同名的空白测试实例。

## 已验证路径

| 步骤 | 实际结果 |
| --- | --- |
| 聚焦Data物品框，系统输入`fuwen` | 输入框预编辑值为`fu wen`；扩展候选按钮0个 |
| 系统空格确认首个拼音候选 | 输入框变为“符文”，出现50个扩展查询候选；前6项为短基底，第7项行家符文，第8项身躯符文 |
| 系统Down八次 | 焦点位于“身躯符文 → Body Rune”按钮 |
| 系统Return | 输入值变为`Body Rune`；原站返回身躯、次级身躯、高级身躯、完美身躯符文4项；保留中文查询提示 |
| 选中英文查询后删除，再系统输入`fu` | 预编辑值为`fu`，扩展候选0个 |
| 组词中系统Escape | 输入值清空，扩展候选仍0个；没有提交半成品英文或中文候选 |

事件记录显示compositionstart、compositionupdate、拼音input和keyup的isTrusted为true。确认与取消时观察到的compositionend为false；没有查明该结束事件标记的来源，不宣称所有事件都带可信标记。真实IME证据来自已运行的Fcitx5及系统按键、可信预编辑事件与实际中文确认结果的组合，而非单独依赖compositionend。

确认“符文”后没有立即替换为英文，仍由用户选择候选触发原站查询。取消时没有遗留扩展候选。尚未覆盖输入法翻页、混合输入、跨输入框切换、重载、长时间连续输入和其他平台。

## 清理

完成后关闭该隔离浏览器和本轮误连产生的空白实例；通过独立D-Bus的`fcitx5-remote -e`结束输入法，启动脚本退出并清理其Xvfb。测试进程正常退出，未改变用户输入法配置。临时目录中的自造输入记录不作为产品数据随扩展打包。
