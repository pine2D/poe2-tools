# 工程教训与收敛约定

2026-09-26。用户指定参考本机安装的PoE2“说”中文0.5.5.3，并指出过度复杂、零碎迭代及token浪费。本文约束后续施工，不代表未验收功能已完成。

## 根因

把“准确转换中文文本”与“保证CoE导入后完全一致”绑在一起，形成基底、词缀ID、等阶、范围的人工准入名单。已经有唯一英文译文的装备仍被拒绝，逐件开通消耗大量工作且不能获得通用能力。这是扩展自己增加的复杂度，不是汉化的必然要求。

只核对JSON导出也不够：0.1.108发现属性面板翻译污染POB文本，0.1.109又发现经典词缀与高级词缀为两套DOM。有效教训是识别原站真正读取的文本并保留它，而非无限增加装备样本。

## 后续边界

- 扩展负责词典、模板、字段和数字结构的准确转换；原站负责装备合法性、词缀归属、制作规则及最终解析。
- 删除逐基底／词缀ID／等阶范围的准入名单。多个ID对应相同英文不构成翻译歧义。
- 保留未知关键行、实际译文歧义、损坏结构与数值的诊断。原文和未识别内容不能静默丢弃；不制造缺失范围或等阶。
- 已知CoE拒绝、丢失或重算行为单独提示，不冒充翻译失败或重建游戏规则。咒符与传奇继续遵守用户仅供对照的约定。
- 原有实测基底作为回归样本，不再决定哪些装备有资格转换。翻译完整、原站接受和结果保真分别描述。
- 不改旧制作网站或旧桥接器的业务语义；扩展只复用文本解析与翻译结果。

## 执行方式

以完整用户流程为交付单位，合并相关修改和文档，不再为个别基底或短文案连续碎片发版。修改先有针对性失败回归，完成后一次跑相关检查；完整门禁放在集成节点，不因没有新变化重复运行。

真实浏览器验收按有差异的结构挑选代表样本，覆盖输入、显示、原生复制／导出和恢复；不穷举“所有基底×所有词缀×所有等阶”。用户暂不便人工验收时继续自动验证，Windows输入法、国服真机行为等仍明确留待确认。

参考扩展仅学习产品行为和模块分工；其CoE支持被作者列为实验性，声明支持不等于完整验收。其专有代码和词库不进入本仓库。现有独立词典与来源登记继续使用。
