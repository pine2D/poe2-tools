# CoE 词缀翻译契约

0.4.4 起，扩展使用独立的原始词缀投影，结束直接消费 `.build` 数字归一化词典的路径。它处理文本，不判断装备是否合法，不为每个基底建立准入名单。

## 来源与投影

| 数据 | 用途 | 约束 |
| --- | --- | --- |
| `data/l10n/stats/zh-CN.json` | 页面简体词缀、中文检索和输入 | 官方英文与国服同 ID 对齐；只把源 `#` 作为变量 |
| `data/l10n/stats/zh-TW.json` | 繁体及混合装备输入 | 独立读取台服；不参与简体显示、不繁简转换 |
| `data/l10n/stat-decisions.json` | 同英文多译文的展示取舍 | 显式来源 ID 与理由；其他译文仍可反向输入 |
| `data/l10n/coe-beta/stat-variants.zh-CN.json` | 交易筛选未表达的已核对展示句式 | 记录原始两侧文本、公开页面与理由；来源改变即阻断构建 |
| `data/dict/*/stats.json` | 旧 `.build` 与旧制作调用方 | 保持兼容投影，扩展不再把它用于词缀匹配 |

官方静态端点没有游戏版本字段。原始投影记录各服 URL、时间、SHA-256，游戏版本为 `unknown`；不能把 CoE 页面版本或抓取日期套给三服，更不能据此更新天赋、宝石或制作目录。

生成器只折叠换行、剥离交易后缀、合并同模板同译文。`every 4 seconds` 的 `4` 保持字面值；只有 `#` 可以接收数值、符号或范围。手工裁决不能把不同英文模板混为一个，也不能用于压掉反向输入的真实歧义。

## 共用规则

`l10n-core/createGameLexicon` 同时提供显示、检索、反向输入和诊断。旧 `createLexicon` 接口继续保留；扩展初始化、构建检查及导入词缀已接入新入口。

匹配完整句，原始模板优先于派生。显示时，同一英文已有中文就忽略未译英文副本；显式 `preferred` 只作用于同一英文模板。数值替换只使用声明的 `order`，反向使用其逆排列。固定数字不被归一化，正负号、双端伤害与括号范围不重算。

提高／降低派生仅允许一个明确由 `#%` 修饰的 `increased`，且中文只有一个“提高”或“增加”，没有对应“降低”或“減少”。不交换 more/less，也不替换条件中的任意 increased。派生文本同时用于显示、中文搜索和输入；输入缺少实际数值、仍带 `#` 时拒绝转换。

已核对的咒符栏／位别名和猛攻 second／seconds 规范归入同一词缀核心。物品类别、技能标题、最高等级、特殊词缀来源及补丁尾注仍由 `item-core` 的结构解析处理；它们不是可随意替换的普通词缀。旧制作调用方未传入扩展解析器时沿用原行为。

## 页面边界与诊断

普通 UI 层避开 `.stat`、物品属性以及 `.modGroup`、Data 的词缀标签区域；只有独立标签继续按界面词处理。中文层使用独立 Shadow DOM，原站关键词节点、事件和原文保留。未识别的新内部结构也不能退化为逐词翻译。读取显式 `<br>` 为换行，避免 `textContent` 将两侧单词粘连；不对相邻单词猜测插空格，不改写原站节点。

已识别词缀块的 `data-poe2-l10n-stat-status` 是本地诊断：`translated`、`unmatched`、`ambiguous`、`source-untranslated`。它随节点更新，停用即清理，不存储或上传装备文本。

`unmatched` 只说明当前完整文本未命中，不能自动断言“官方缺项”或“展示变体缺项”。维护者应将原文与原始快照对照后分类；语义容器存在但没有支持的文本节点，则属于结构适配缺项。无法确认的整句保留原文，不逐词猜译。

## 覆盖门禁

`apps/poe2-extension/tests/stat-coverage.test.ts` 直接构建实际扩展词典，进入 `test:active` 与完整 `verify`：

- 当前快照 3,706 个简体展示条目：逐条检查完整模板、未译原因及固定数字误匹配。
- 来源审计另行锁定：简体 636 项未配对标记；繁体 2,314 项未配对、1 项占位符不一致、33 个仍为英文的条目、6 组同英文不同译文。原始投影中的 `audit` 与两侧快照保留这些证据；不能把它们从“来源是否完整”的结论中抹掉。未配对计数沿构建器的 ID／语境发生项口径，不是 CoE 当前装备词缀的缺失数。
- 7,420 个简繁输入条目：用互不相同的自造数值检查正确英文候选未丢失、不会错误地唯一化其他译文。保留歧义不等于自动输入成功。
- `tests/fixtures/stat-corpus.json` 的 30 条冻结语料：攻击、护甲、属性、药剂、咒符、召唤生物、技能、地图、条件、固定数字及未知负例。译文不通过运行时生成。
- 页面边界测试检查未知结构、移位、重建、克隆、开关和原文；既有装备导入样本继续回归。

这些分母分别是模板条目和冻结语料，不是 CoE 全站或当前制作池的漏译率。Data 中的历史文本不能混入当前制作流程的覆盖承诺。实际浏览器记录见[系统整改验收](validation-2026-10-20-translation-system.md)。

## 更新顺序

1. 通过既有 `cache.ts` 缓存三服官方端点；手动运行 `pnpm --filter @poe2-tools/dict-builder exec tsx src/build-stat-catalog.ts`，离线加 `--offline`。
2. 核对两侧快照、缺项、占位符差异、裁决是否失效；不要只提高覆盖数字或改基线放行。
3. 展示变体先登记来源与完整条件；不要用繁简转换、运行时大模型或其他扩展词库填空。
4. 跑覆盖门禁和浏览器矩阵，检查原生复制、动态更新、关闭恢复；有包内容变化就升扩展版本、更新日志和 `release.json`。

页面诊断、来源自检、词义正确性和真实浏览器兼容性是不同证据，任何一个都不能替代其他三个。
