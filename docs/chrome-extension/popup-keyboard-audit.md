# 设置开关键盘焦点验收（2026-09-26）

## 缺陷与修复

Linux Chrome151，0.1.102独立实装后，打开扩展popup.html文档，聚焦双语开关并实际按Space。保存成功、checked为true，但document.activeElement变成BODY：保存期间临时禁用当前控件导致失焦，下一次空格无法继续切换。

0.1.103在保存前记录当前开关是否持有焦点；保存结束并恢复控件状态后，仅当原焦点属于该开关且当前焦点仍为body时归还焦点。若外部设置使原双语开关不可用，则回到启用开关；若用户已聚焦其他控件，不抢回。成功与失败均遵循此规则，不修改设置读写、并发事件取舍或禁用策略。

## 验证

新增四项回归：保存成功恢复、保存失败恢复、用户转移焦点不抢回、外部停用时回到可用开关。前三个恢复场景在实现前失败。happy-dom不会完整复现Chrome禁用控件的失焦行为，测试用可聚焦body显式模拟实站观察到的焦点，不将模拟结果当作浏览器证据。

最终0.1.103 ZIP独立实装，真实Space切换双语后焦点为bilingual；不重新focus，再按Space成功关闭双语。Shift+Tab返回enabled，Space停用后焦点仍为enabled且双语禁用；再次Space启用，Tab回到bilingual。使用的是真实扩展popup.html文档，不声称已测试工具栏弹出窗口生命周期或读屏播报。保存失败、外部更新与不抢焦点边界由DOM回归覆盖，未在Chrome伪造存储故障。
