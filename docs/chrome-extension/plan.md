# 新版 CoE 简体中文 Chrome 扩展实施计划

> 执行者：使用 `superpowers:executing-plans` 按任务推进。用户已于 2026-09-24 授权施工；本计划保留完整路线，0.1.0 开发预览的实际结果见 compatibility.md，未勾选项仍未完成整项验收。

**目标：** 交付在新版 CoE 的 PoE2 模式中可安装、可关闭的简体显示、中文搜索与中文装备导入扩展。

**架构：** `apps/poe2-extension` 包含 Chrome 平台与 CoE 适配，`packages/l10n-core` 包含纯术语匹配；装备文本沿用 `item-core`。词典随包发布，原站承担制作运算。

**技术栈：** 现有 pnpm、TypeScript、Vite、Vitest、happy-dom，Chrome Manifest V3；不新增生产依赖。

**设计：** [设计与文件安排](design.md)。本文是阶段与文件级实施安排，具体 DOM 定位必须来自任务一的实测，不能预写未经验证的选择器或事件桥。

当前完成证据与剩余施工优先级见 [阶段审计](stage-audit.md)（当前0.1.93，保留0.1.48初次审计）。勾选仅表示该子项证据已核对，不代表所在阶段或完整扩展已全部完成。

## 全局约束

- 首站仅 `https://beta.craftofexile.com/*`，仅 PoE2、英文基准；旧站与 PoE1 不适配。
- 仅国服简体，不以繁简互转填补；保留数字、身份、未知行和原站操作语义。
- 原独立模拟网站无限期搁置，不恢复制作规则、概率或策略引擎开发。
- 只在各任务开始时创建其文件，不先生成空目录／空实现。所有新文件职责见设计文档。
- 用户已授权实施；不把规划提交或单元测试当作原站完整兼容性证明。
- 每个实现任务按失败测试 → 最小实现 → 相关验证 → 精确暂存提交推进；不得以测试数代替浏览器端到端证明。

## 重点审查

1. 原站复用节点并更新数字时，关闭汉化不能恢复陈旧装备值（任务三）。
2. 中文输入法连续组词、清空、粘贴与延迟结果交错，不能提交旧查询（任务四）。
3. 相同译名在物品／词缀／材料中含义不同，不能跨领域自动选择（任务二、四）。
4. 缺失高级范围、复合词缀与重复文字行，不能丢失语义后声称导入成功（任务五）。
5. 切换游戏／原站语言、重新挂载和扩展更新后不能重复监听或误处理备注（任务一、三、六）。

## 任务一：完成新版站点接入调查

**文件：** 新增 `docs/chrome-extension/compatibility.md`；自造 DOM 样例放 `apps/poe2-extension/tests/fixtures/`，不保存原站全页 HTML。

**输入：** 用户确认的英文模式、PoE2 范围；**输出：** 页面／搜索用途／定位特征／触发方式／成功证据表。

- [ ] 使用隔离浏览器核对基底搜索、词缀搜索、材料搜索、装备导入弹窗；另覆盖 Data 搜索、Simulator 流程节点和 Inventory 界面。
- [ ] 每种输入分别记录输入事件、异步结果、清空、重新挂载与原站语言切换；定位仅依据页面可观察 DOM，不读取同行执行源码和数据文件。
- [ ] 同一基底对照中文原词与英文查询；等待结果稳定后核对候选，不把瞬时空列表当失败。
- [ ] 检查翻译目标是否被站点读取用于过滤或复制；需要保留原文本的节点在兼容性表中指定叠加显示方案。
- [ ] 写出按上下文启停与控件特征失败的行为。任一控件未核实则留在兼容性清单，不对全页输入框启用猜测替换。
- [ ] 审查调查记录，提交 `docs: 核对新版 CoE 扩展接入点`。

## 任务二：国服术语核心与构建资源

**文件：** 新增 `packages/l10n-core/`、`data/l10n/`；新增扩展 `scripts/build-dictionary.mjs`。按实际需要修改 `package.json`、锁文件、`.gitignore`；来源先登记 `docs/data-sources.md`。

**边界：** 纯核心输入已加载的术语记录，输出显示匹配或英文候选；不读文件、不操作 DOM、不使用 Chrome API。记录包含稳定 ID、英文、国服译名、领域、别名、来源和快照版本。候选携带匹配方式，唯一精确匹配与近似候选明确区分。

- [ ] 先写合成词典回归：`冰霜抗性` 匹配 `Cold Resistance`；同名不同领域保持多候选；未知词返回未命中；已有英文原样保留。
- [ ] 为显示模板写失败测试：`+18% to Lightning Resistance` 的数字18和符号不变；两数值模板的占位顺序按来源映射而不是出现顺序；固定数字不当占位符。
- [x] 实现索引、显示与检索；只复用已核对的现有纯函数，避免引入完整 `.build` 或制作引擎。
- [x] 实现构建资源：裁剪已登记国服表，输出术语、UI 文案及来源哈希。关闭 gray 来源后重建不得残留灰区条目；不硬编码装备用词弥补缺词。
- [x] 运行 `pnpm exec vitest run packages/l10n-core` 和该包 typecheck；审查资源体积、许可与版本，不把翻译匹配数当导入兼容数。
- [x] 提交 `feat: 建立扩展国服术语匹配核心`。

任务二勾选证据：阶段审计第二节。实际核心交付包含在`d426303`中，提交标题与原拟标题不同；本轮使用同一本机Vitest／tsc入口直接执行，等价于上述脚本调用。前两项现有回归已覆盖，但本轮未追溯最初失败测试记录，保留流程复核项，不据单个实现提交推断先后顺序。

## 任务三：可安装扩展与可恢复显示层

**文件：** 扩展 manifest、package/config/scripts、popup、settings/platform/dictionary、content 的启动／观察／显示、CoE context/selectors/regions、自制 icons；补充根脚本。新增 `docs/chrome-extension/install.md`、`privacy.md`。

**边界：** 内容脚本消费任务二资源，通过任务一明确的区域显示；设置由 popup 与 content 共享，从扩展内关闭汉化时由显示层恢复原文，不能依赖刷新页面。浏览器管理页禁用／卸载扩展后按设计提示刷新已有标签页，不承诺已失效脚本还能主动清理。

- [ ] 自造 DOM 测试先覆盖：原文→译文→原站更新→新译文→关闭恢复最新原文；重复初始化只挂一个观察器；移除节点可释放；未命中原样保留。
- [ ] 写上下文与权限检查：旧域名、PoE1、未知模式不处理；输入框 value、URL、业务属性和站点 storage 保持不变。
- [ ] 实现按区域增量更新、节流、原文所有权、启停与中英对照；不遍历替换整段 innerHTML。
- [x] 实现两个独立构建入口，确保内容脚本是可独立执行的 IIFE，无意外 import／远程引用，popup 和内容资源不会被第二次构建清空。
- [x] 新增根 `extension:build/check/package` 脚本；清单检查固定域、storage 权限、版本一致、入口存在与 JSON 资源限制。产物和 ZIP 不入库。
- [ ] 运行扩展相关测试、typecheck、build/check；在真实 Chrome 加载 dist，验证 popup、内容脚本、设置持久化与关闭恢复，而非只用页面 eval 验证。
- [ ] 提交 `feat: 接入新版 CoE 简体显示扩展`。

## 任务四：中文搜索驱动原站查询

**文件：** `src/content/search-controller.ts`、`src/adapters/coe-beta/search.ts`、`src/ui/candidate-list.ts`、相应 tests；更新兼容性表。

**边界：** 核心提供领域候选，控制器管理中文查询／英文执行值，适配器定位并提交原站控件。价格、备注、流程名称及未知输入框没有适配器，保持原样。

- [ ] 先写组合事件测试：composition 中不提交；结束后一次提交；快速后续查询丢弃旧结果；清空回到原站无筛选状态；Escape 取消候选。
- [ ] 写领域歧义、部分词、多词混输、已知英文、未知中文与候选键盘导航测试；近似结果不能自动替换为唯一身份。
- [ ] 按任务一实测触发原站检索，加入中文查询可见提示与继续编辑路径，不把候选映射藏成不可解释的输入跳变。
- [ ] 真实 Chrome 逐项验证基底、词缀、材料及 Data 搜索：匹配结果与手输英文相同，选择后后续制作可操作，汉化的显示文本不干扰站点检索。
- [ ] 运行核心与扩展相关测试、类型和打包检查，提交 `feat: 支持新版 CoE 中文术语搜索`。

## 任务五：中文高级装备导入

**文件：** import-controller、CoE import、ui/import-panel 与相应 tests；按需要对 `item-core` 文本模块增加独立兼容接口及回归，不改旧转接入口的既有验收语义。

**边界：** 文本解析结果和用户明确选择 → 英文转换预览／诊断 → 原站导入。`exportText` 可产生不完整翻译，不能直接等同于“可导入”；资格由本扩展已验收结构决定，而非本机制作引擎的允许材料集合。

- [ ] 先写合成国服文本矩阵：法器、腰带、权杖、普通武器、防具、首饰；另含咒符／传奇只读对照、腐化、孔位、品质、复合词缀、缺等阶、逆序范围及未知行。
- [ ] 验证每行身份、数值、范围、分组与原文保留；非法或歧义文本不自动提交；交易备注与有语义的词缀行分开处理。
- [ ] 实现粘贴转换入口和双栏预览，按用户提交动作填入原站导入框，不后台读取剪贴板、不在日志持久化全文。
- [ ] 真实 Chrome 从法器试点开始逐结构扩展，核对原站实际导入后的基底、词缀、数值和标记；保存覆盖表，不能以本地英文输出测试代替导入成功。
- [ ] 核对 CoE 不支持的装备仍可翻译对照并明确提示，不强行开启制作；剩余未支持结构列为实际限制，不能声称全装备覆盖。
- [ ] 运行 item-core 被修改模块与扩展回归、类型、打包检查，提交 `feat: 支持国服高级装备转换导入 CoE`。

目录／职责对应设计第二、三节；任务二覆盖术语来源，任务三覆盖权限和显示恢复，任务四覆盖中文输入，任务五覆盖文本导入，任务一与六覆盖新版站点和真实安装。三个用户流程均有原站结果核对，不依赖旧模拟器的完成状态。未安排重新获取权重、复制 CoE 数据或恢复旧路线。
