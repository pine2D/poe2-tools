# 装备高级剪贴板文本

本页记录装备工坊已实现的结构与适配边界。样本依据为 2026-09-12 提供的四份国服真机 Ctrl+Alt+C 文本（咒符、法器、权杖、传奇法杖），原始样本只保存在 `data/fixtures/local/`。这不是官方完整格式规范。

## 输入与分组

身份区由物品类别、稀有度和名称行组成，`--------` 分隔后续属性区块。解析保留完整原文和原始行号，并独立记录物品等级、需求、插槽、授予技能、特殊状态和备注。当前语法入口包括 zh-CN、zh-TW 与 en；真机验证仅覆盖上述国服样本，其他语言使用合成语法测试，不宣称全覆盖。

`Sockets: S`／`插槽: S` 不保证孔为空；公开装备复制样本存在 S 与 rune 效果同时出现的情况。当前不从该字母反推孔内物，原文保留供查看。常规防具可单独声明实际孔数和孔内物，项目记录为用户核对；S 的数量必须一致，缺行默认未知。未知镶嵌效果仍拦截，声明不能删除原文语义。搜索起点的显式已有空孔设置属于演练初始条件，不能冒充导入解析结果。

独立护甲、闪避、能量护盾等已知面板行作为 properties 保留原值，不混入词缀；识别面板行不代表已实现制作后的面板重算。

独立行尾 `(rune)` 归为 runes 区块，保留原文与行号，不创造虚构属性头或计入前后缀。已有词缀或描述上下文中的相同字样不改分类。英文实证来自公开玩家高级复制，简繁兼容采用合成测试，真机待验收。译法通过各自词典独立反查；三系抗性可与显式选择的孔内物总贡献核对，未知效果仍保留并拒绝制作。英文 `Requires:` 与 `Requirements:` 均作为需求区块保留。

```text
{ 后缀属性 "示例之" (等阶：1) — 魔力 }
魔力再生率提高 19(18-22)%
照亮范围提高 15%
```

上例是**一个后缀、两行属性**。词缀数量按属性头计数，不能按显示行数计数。基底属性、腐化强化、传奇属性分别保留分组。未知头或无法分类的内容保留并给诊断。

`22(23-21)%` 中 22 为实际值，括号是有方向的显示范围，原始端点顺序 `[23, 21]` 保留；不把阶级、物品等级混入 roll。每个属性行允许多个带范围或不带范围的数值。`— 数值不可估量` 单独标识，不参与词典模板匹配。

高级固定属性的 `15(15)` 或 `18(15)` 分别保留当前值与固定基础值（`Roll.baseValue`），只计一个 roll，不伪装成 `[15,15]` 可变范围。翻译和三语导出保留整个注释。目录仅在当前值、基础值与目录固定值均精确一致时允许对应；数值不同则保留原文并提示增效来源待还原。固定基础值不参与神圣重掷，已核对注释随历史和项目恢复保留。此格式依据固定 PoB 快照，中文真机样本仍待验收；不同固定值的逆算尚未开放。

普通 Ctrl+C 缺少高级属性头时仍可查看原文，但不会猜测前后缀和阶级。缺物品等级不自动填默认值。输入上限 200000 字符。

## 术语解析

词典复用 `data/dict/<locale>/items.json` 和 `stats.json`。zh-CN、zh-TW 使用各自词典，不作繁简互转。基底名称和属性模板的反查保留全部候选；只有唯一英文结果或用户选中已有候选时才采用。

制作目录将英文名称与内部基底身份分开。同名的不同固有属性或基础面板分别保留，内容 ID 不写进导出装备名称；只差隐藏标记的重复声明合并显示并保留来源。多变体导入不能仅凭名称默认选第一项，完整固有属性和范围能唯一对应时自动定位，否则保留候选供核对。物品等级不用于猜选更高等级基底；单声明内部的技能 variantList 选择仍待接入。

数值回填保持正负号、百分号、小数与范围。中文占位符 `order` 必须是可逆排列，并使用逆排列恢复英文顺序。属性模板的固定字面数字不是占位符。

交易词典可能只给 `increased` 形式；与现有 Build 翻译对称，仅当英文 increased 和中文提高/增加都唯一、没有相反方向词时，允许生成 reduced 与降低/減少的精确回退模板。优先采用原始模板，不推断其他语义或模糊替换。

匹配到 trade stat id 不等于识别出游戏生成 mod id。工坊另用固定 PoB2 目录对应常规生成词缀：核对基底生成资格、前后缀、整组全部英文属性行、实际值与高级范围。属性显示顺序可以不同，缺少一行不能匹配混合词缀。固定数字按原值核对；范围方向不影响数值集合，但原文仍保留显示顺序。英文原文可以直接与目录核对。

缺少高级范围时保留所有满足数值条件的候选，不以原文阶级、当前物品等级或词缀名猜生成 ID。未对应或未翻译的属性继续保留，已对应并不证明装备全部状态可制作。当前阶级仍来自剪贴板；本地指定结果演练范围见 crafting-rules.md，真实概率模拟尚未实现。

## 只读与转接

咒符和传奇是「仅供对照」类别。不因解析出前后缀而开放制作。其他类别能够解析也不代表已验证可制作。

CoE 转接放行已黑盒核对过的 **23 种普通法器的魔法、稀有装备**，以及能量护盾上限、冰霜伤害、魔力上限、闪电抗性、魔力再生率和混沌抗性六类单行常规词缀。魔法最多一前一后，稀有最多三前三后；要求物品等级、前后缀与阶级明确。未知结构、特殊状态、混合词缀、授予技能或插槽尚未验证时阻断转接。范围之外仍提供原文和可识别英文对照。具体基底和验收方法见[法器转接核对](coe-focus-bridge-research.md)。

2026-09-12 使用合成法器在 CoE 默认英文界面验证：英文属性与高级描述可保留原中文 mod 名和 tag；CoE 还原出正确英文词缀名、前后缀、tier、roll 及范围。不为通过导入而捏造英文 mod 名。此行为是目标站观察结果，不是其长期兼容承诺，扩展范围时需追加验收。

CoE 接口为 `https://beta.craftofexile.com/?game=poe2&eimport=<编码文本>`。按钮只在用户点击时导航，发送的是已适配文本，不含交易备注和风味段落。英文对照草稿保留未识别语义原文，不能冒充可完整导入的英文装备。[CoE 开发者文档](https://beta.craftofexile.com/developpers)

## 数据与测试边界

解析器没有网络请求。词典来自本站静态资源；关闭灰区物品名表时降级为原文与未识别提示。新制作数据源或扩展抓取范围仍需先登记，不复制 CoE 代码、数据包或未经许可的中文数据。

入库测试均为改变名称和值的合成样本；四份真实样本仅用于本地验收。待扩展：更多基底和词缀的完整转接、其他授予技能语法与特殊状态适配、带版本证据的制作数据和规则、真实权重来源。不能用本页的有限样本命中率代表全游戏覆盖率。

## 演练结果三语文本

工作台可将当前已应用的 `CraftState` 生成为独立高级分组文本，供查看、复制、下载及回到本站解析核对。文本从当前状态和固定目录重新生成，不复用 `sourceText` 中的随机名称、交易备注、旧面板和需求；稀有装备名称行使用明确的演练占位名（`Crafting Simulation`／制作演练／製作演練），末尾备注说明演练来源与完整项目恢复方式。

前后缀按整组输出，保留目录名称、标签、实际行及 `(crafted)` 标记。目录缺少可靠 Tier，所以不把 `mod.level` 当作阶级；命名普通属性头允许省略完整 Tier 段，畸形段及特殊标记仍拒绝。导入继续按完整组、范围和基底资格唯一匹配，同文档位不猜选；既有 CoE 转接独立要求明确 Tier，未因此放宽。

固有属性和授予技能保留当前行，技能与普通 implicit 分块；已知品质输出 Quality，未知品质不填零。孔数已知且大于零时输出 S 数量，当前符文效果从已核对孔内物重新生成独立 `(rune)` 行，不能复用起点旧效果。零孔省略无效空 Sockets 行；S 本身不能记录孔内身份或孔序，再导入仍需核对，精确信息用 `.craft.json` 恢复。

未定值范围原样保留并提示，不取最小值冒充实际数值；不生成未核验的攻击／防御面板和最终穿戴需求。未对应目录的技能、其他未支持语义及文本同文歧义可能使回读只能对比，保留原信息并说明原因。三语演练文本不是完整游戏 Ctrl+Alt+C 格式的兼容承诺，全类别第三方保真仍待扩展。

导出面板默认简体中文，也可选择繁体中文或 English。展开后按需加载该语言的本站静态词典；加载失败可重试或选择无需词典的英文输出。词典与剪贴板的迟到反馈随语言、装备和展开状态变化失效，导出语言不进入制作历史或项目规则版本。

中文基底名只在 items.bases 中唯一反查到当前英文名称时采用；属性按现有正向模板翻译，生成词缀／符文附带目录 trade hash 消歧，再用全局中文反查检查数值与语义未变。缺表、缺译文、同译名、多义、不可逆或结构字符异常均保留英文原行并说明。类别值、词缀名称和标签保留目录英文，不猜完整游戏术语。

授予技能使用同一语言的官方 skill.* 模板，保留显示等级、可选最高等级和无等级形态。缺少模板的英文技能保留原文；中文文本中的规范 Grants Skill: 行按既有英文语法解析，仍须与当前基底的完整固有属性核对一致，不能把任意英文技能当作可制作证明。中文技能只查本语言模板，不交叉猜译。

制作目录加载后，以其已有英文名称补充基底身份；原 items 译名优先，缺灰区 items 表时也能识别目录已知的英文名称。内部 ID、变体哈希和模糊拼写不会加入身份字典，真实名称碰撞仍要求消歧。项目恢复共用此字典后重验原文、全部属性和操作；此处只扩展回读，不单独改变项目格式；v11 技能来源与 v17 无等级技能来源门禁也覆盖中文包裹英文的形态。目录加载不会另发请求或重置正在进行的历史。

产品流程参考 [CoE 的导入导出与装备展示说明](https://beta.craftofexile.com/whats-new)；其[开发者文档](https://beta.craftofexile.com/developpers)只提供 URL 导入集成说明，没有保证任意生成文本都可导入。本功能无外发请求，未复制其代码或数据。


## 授予技能行

装备工坊已支持按官方 skill.* 整行模板反查带等级技能名称，分别保留显示等级及可选最高等级（规范英文 Max Level）。不把技能数字当作普通词缀范围，技能不占前后缀。未知/多译法保留原文，用户可选择已有候选；最高尾注不被翻译丢弃。通过目录完整对应的普通装备可以进入显式制作，项目保留完整技能固有行及来源；不代表已计算角色最终技能或已验证神圣交互。

无等级行使用 `Grants Skill: 名称`、`获得技能: 名称`、`賦予技能: 名稱` 语法。名称从官方 skill.* 模板独立提取，招架对应 Parry、架盾／舉盾对应 Raise Shield；当前词典缺少 Spear Throw 译名，不猜中文。此形态的显示等级与最高等级均为空，不产生起点等级输入。制作时须与当前基底的静态技能行完整对应，不能把损坏等级行、最高等级尾注或其他技能作为同一形态放行。规范无等级技能可随英文或中英混合演练文本回读，仍不开放额外 CoE 转接。

## 特殊词缀来源

属性行尾的英文 `(crafted)`、`(desecrated)`、`(fractured)` 分别保留为工艺、亵渎、破裂来源，与前后缀位置独立。中文属性也可带这些英文尾注；目前没有验证中文客户端是否使用其他中文状态写法，不猜别名。明确英文前导 `Crafted / Desecrated / Fractured Prefix / Suffix Modifier` 也可识别；词缀名称和数值不能用于推断来源。

每行分别保留状态，组内汇总去重；混合词缀仍是一组，未标记行不会继承另一行的状态。已知尾注与不可缩放标记可以组合，未知括号仍按原文保留。英文词典候选及最终对照重新附带状态，不因去尾注匹配而抹掉语义；目录词缀身份可以单独对应，但不能据此认定可制作。

独立 `Fractured Item` 识别为破裂物品旗标，不自动把全部词缀设为破裂。原文、行号、范围及状态均保留，页面显示中文来源徽标。v15允许原文明确且唯一可核验的工艺组进入演练，属性行去已知状态尾注后与目录对应，状态独立保存；不从工艺标记猜材料身份。v20进一步允许已揭示且唯一对应的稀有装备亵渎组进入制作；破裂、未揭示与未知来源继续拒绝，CoE转接仍限已验证范围。门禁重新解析原文核验，不能通过删掉派生状态字段绕过。v2–v14项目不能借来源文本注入新工艺能力。游戏操作和简繁状态语法真机验收仍待做。


## 武器符文来源

武器、法杖和施法长杖的 `(rune)` 来源行已扩展到四族普通符文：固定附加火／冰／电点伤、本地物理提高、获得额外元素伤害及法术伤害提高。多个孔可以被游戏文本合并为一行，按语义分别核对总和；必须声明全部孔内物，不按行数判断孔数。中文按现有三服模板独立反查，未知与歧义仍保留。

英文演练文本按当前类别和孔内物重新生成符文行；覆盖不会把起点旧符文带入结果。S 仍只表明孔数，文本回读要求重新核对孔内身份；完整来源与历史使用当前项目格式恢复。更多武器复制语法和真实客户端行为待验收。

武器本地面板在演练界面单独按当前状态估算，不写入英文导出文本。导入的伤害、攻速或暴击面板不作为再计算基础，避免将已增强值再次增强；品质仍只取明确属性行或人工声明。

原始武器面板可识别五系伤害区间、合并元素伤害（最多三段）、暴击百分数、攻击每秒与装填时间的英文、简体及繁体标题；完整整行分类为属性，保留小数、分隔符和 augmented 标记。无效数值形态或未知尾注继续保留并诊断，不把词缀组内的同名文本转移为属性。当前三语武器验收使用合成输入，更多真实游戏复制样本仍待补充。


## 已揭示亵渎来源回读

英文字段 Desecrated Prefix/Suffix Modifier 或属性行尾 (desecrated) 明确标记来源，三语文本都保留该尾注；不凭词缀名、族名或数值猜来源。目录中普通词缀也可带亵渎来源，专属词缀必须带来源。一次只接受一组已揭示亵渎，允许另有一组工艺，两者不能重叠到同一组。

导入先重新解析完整原文，核对派生物品与词缀组，禁止删去状态、旗标或其他字段绕过；随后核对基底、整组范围、固有属性、品质、技能和孔位。普通通货保留尚未移除组的来源，神圣可重掷已支持数值；混沌、剥离或替换精华移除整组后，新的普通／工艺组不继承亵渎。三语输出保留当前来源，未译内容保留英文。

v20项目保存ModVeiled来源指纹及起点亵渎状态，并回放全部历史；v2–v19不能夹带新字段、亵渎原文或专属状态，原本合法项目可核对后升级。v20仅处理已揭示且可对应的来源；下述v21另行接入骨骼与三选一演练，不宣称全游戏剪贴板或真机互动完成。

## 骨骼制作中的未揭示状态

v21 的未揭示占位来自已验证的骨骼步骤，保存材料、前后缀位置及已固定的三项候选。它不等于普通空位，也不作为虚构的目录词缀输出。未完成揭示时应保存 `.craft.json`；装备文本导出明确拒绝，避免悄悄丢掉隐藏状态。游戏原始隐藏剪贴板语法仍未完成兼容，不推断未知中文标记。

选择完成后使用既有三语输出，当前选中词缀带 `(desecrated)`，其他候选不写入装备。项目从原空白/导入起点重放完整历史，即使当前游标停在施加或给出候选后也能恢复；旧 v2–v20 不能夹带新占位或新操作，合法 v20 已揭示来源仍可升级。


## 腰带咒符栏（v22）

完整固有行保存当前栏数和原始范围：英文 Has 2(1-2) Charm Slot／Slots、由各自词典对应的简体“具有 2(1-2) 个咒符栏”和繁体“有2(1-2)個護符欄位”。英文复数只在槽行局部归一，不放宽其他数值或词缀匹配。高物等旧范围仍保留，不能因目录显示1–3而升级。

plain Has 2 Charm Slot只证明当前2栏；没有范围证据时可继续其他支持制作，整个神圣操作受限，不能假装只重掷其他属性。目录原生固定1栏基底依固定模板核对。可选面板Charm Slots／咒符栏／護符欄位只核对与固有当前值一致，不作为范围来源；重复、冲突、缺失固有行或篡改解析结果拒绝进入制作。中文面板标题属于采用官方术语的工具支持语法，尚未取得用户原始腰带真机文本。

搜索起点仅允许声明栏数，其他普通固有属性仍不预设实值。项目起点必须保留完整implicitLines并重验原文；v2–v21不能携带此前未支持的charmLimit腰带能力。生成文本以当前固有行输出，完整历史仍由.craft.json保存。


## 固有目标与文本（v23）

目标条件关联固定基底目录位置，与高级文本行顺序和中文译名分离。导入仍保留原文实际数值/范围；设定目标不改原文，不为缺范围装备补值。三语装备结果不嵌入目标配置；完整目标以演练项目targetImplicitValues保存，重新导入装备后可重新配置，或导入.craft.json恢复。


## 骨骼目标与待揭示项目（v24）

亵渎专属目标通过项目原 targetModIds/targetValues/targetAlternatives 保存，不嵌入装备文本。骨骼后、固定三候选后均使用 .craft.json 保存并继续；待揭示状态仍不导出伪造装备文本。选择揭示后沿用既有三语高级文本和亵渎来源标记，重新导入仍核对原文、词缀身份和来源。固定候选与目标配置独立，改变目标或重新规划不会自动替换原三项。

催化品质标题单独分类为物品属性；括号内英文类型按固定来源识别，未知中文类型保留待用户核对。属性头末尾的百分比增效独立保留为 magnitude，不混入标签；CoE 转接尚未核验时明确拒绝。已有品质的完整高级基础范围可导入制作，三语导出使用已核对的英文 Quality 标题并保留基础数值，具体边界见 crafting-rules.md 的 v36 说明。
