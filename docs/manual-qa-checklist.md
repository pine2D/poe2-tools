# build-l10n 真机走查清单

自动化测试与 Linux 无头 Chrome 的截图**不能**替代这份清单：字形回落、`background-clip: text`、
`:has()`、`env(safe-area-inset-*)`、高对比度主题这几件事，结论只能来自真机。
每次界面有较大改动（改版、发版）跑一遍，把结论写进当次的执行报告，不要写进本文件。

跑之前：`pnpm --filter @poe2-tools/build-l10n build`，把 `dist/` 放到局域网能访问的地方，
或直接用线上站 <https://poe2-tools.pages.dev/>。手边准备一份真实的 `.build`
（`data/fixtures/synthetic/rich.build` 也行，但真实导出更能暴露长行与传奇装备的问题）。

## A. Windows Chrome（桌面基准，1440 宽）

| # | 看什么 | 怎么判 |
|---|---|---|
| A1 | 顶栏字标「PoE2 构筑汉化」 | 金渐变从上到下由浅到深，**字是看得见的**。整块消失 = `background-clip: text` 没生效，记下 Chrome 版本 |
| A2 | 空态大标题 | 同上，且投影没有糊成一圈脏边 |
| A3 | 中文字形 | 正文是雅黑一族（笔画方正），不是宋体（有明显衬线）。**重点看对照表的两条列头**「原文 · EN」「译文 · 简体中文」——它们用的是混排字体栈，掉宋体会与全站不同族 |
| A4 | 编号词缀行对齐 | 一张卡里多行数值的小数点、百分号纵向对齐（`tabular-nums` 生效） |
| A5 | 繁体译文 | 切到「繁体中文（台服）」，译文列的字形是台服黑体，**不是简体字形硬套繁体字**（看「說」「灣」这类字的撇捺） |
| A6 | 主题三态 | 三个选项各点一次，整页立刻换皮；刷新后记得住；选「跟随系统」后去系统设置里改配色，页面跟着变 |
| A7 | 浅色下的可读性 | 浅色主题下逐屏扫一遍：拖放区虚线框看得见、粘贴框边框看得见、未命中的琥珀标签看得清、宝石名的青色不发白 |
| A8 | 键盘 | 从地址栏按 Tab 一路走到底：每个可聚焦元素都有可见金色焦点环，**分段控件（目标语言 / 主题）也有**；按 `N` 跳未命中、按 `F` 切筛选；焦点在粘贴框里时按 `n` 只输入字母、不跳转 |
| A9 | 下载 | 点「下载此文件」→ 底部出现引导条，写着实际文件名，4 秒后自己消失，期间可手动关 |

## B. 微信内置浏览器（X5 / 安卓）

把站点链接发到微信里点开。这是本仓库反复点名的老内核环境。

| # | 看什么 | 怎么判 |
|---|---|---|
| B1 | 字标与大标题 | 与 A1 / A2 同。**若整块不可见**，说明 `-webkit-text-fill-color` 的兜底没起作用，是阻断级问题 |
| B2 | 分段控件的键盘焦点 | 接一个蓝牙键盘按 Tab（或用系统的焦点导航）：目标语言与主题两组都要有可见焦点环。这一条测的是 `:focus-within` 兜底（`:has()` 在老 X5 上不支持） |
| B3 | 折叠粘贴入口 | 「或粘贴内容 ⌄」点得开、收得起；**不支持 `<details>` 的内核会把内容直接展开**，那是可接受的退化，不是 bug |
| B4 | 主题 | 三态切换是否生效（`data-theme` + 属性选择器，支持面很广，理论上没问题，实测确认） |
| B5 | 横向溢出 | 左右滑一下，页面不能左右晃动 |
| B6 | 触控 | 「全部下载」「下载此文件」「跳到第一处」「仅看未命中」「定位」「移除」都能一次点中，不需要瞄准 |

## C. iOS Safari（iPhone）

| # | 看什么 | 怎么判 |
|---|---|---|
| C1 | 页面高度 | 首屏没有被地址栏吃掉一截，底部内容划得到（`100dvh`） |
| C2 | 安全区 | 横屏时内容不被刘海压住；竖屏时底部的下载引导条在手势条**上方**，没被吞掉一半 |
| C3 | 粘贴框聚焦 | 点开「或粘贴内容」再点文本框，**整页不放大**（字号 ≥16px）。放大了就是这一条坏了，而且退不回去 |
| C4 | 侧栏抽屉 | 首屏看不到文件列表，顶部一条「⌄ 文件 · xxx.build」；点开出现拖放区与文件卡片；选一份文件后自动收起 |
| C5 | 下载 | iOS 的下载行为与桌面不同（可能进「文件」App 或直接预览）。**记录实际发生了什么**，这决定我们要不要在引导条里加一句 iOS 专属说明 |
| C6 | 主题 | 跟随系统模式下，在控制中心切深浅色，页面跟着变 |

## D. Windows 高对比度（设置 → 辅助功能 → 对比度主题）

亮色与暗色主题各开一次。

| # | 看什么 | 怎么判 |
|---|---|---|
| D1 | 两个开关 | 「双语」「传奇名注入」的勾选状态与实际一致——**这条曾经反过来**（2a C-1），是本清单里最重要的一条 |
| D2 | 未命中 | 覆盖率轨上的缺口仍然看得见（有边框），图例里那枚空心样本也在；对照表里未命中行的左竖条与行尾「未命中 · 保留英文」文字签都在 |
| D3 | 字标 | 退回系统色的实色文字，不是一块空白 |
| D4 | 当前语言 | 分段控件里选中的那一项有可辨的高亮（`Highlight` 轮廓） |
| D5 | 提示条 | 下载后的引导条有边框，不是一块贴在背景上的文字 |

## E. 游戏内验收（唯一能判「这个工具到底有没有用」的一步）

| # | 做什么 | 怎么判 |
|---|---|---|
| E1 | 把下载回来的 `.build` 放进 Build Planner 目录，同名替换 | 游戏能正常加载这份构筑，不报错、不闪退 |
| E2 | 看备注 | 中文备注**显示出来了**（不是方块、不是空白）。这是整个项目最核心的未验证假设 |
| E3 | 传奇名注入 | 开着「传奇名注入」导出的文件，装备备注里多出来的那行中文名显示正常 |
| E4 | 双语 | 开着「双语」导出的文件，中英两行都在，没有被游戏截断 |
| E5 | `name` 字段 | 构筑名没有被改动（我们不翻它），游戏里显示与导出前一致 |
