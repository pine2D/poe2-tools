# 制作收尾与装备技能辅助孔核对

## 2026-09-17 v103：已选技能项链辅助孔

重新核对 GGG 0.5.0 Item Changes：工匠石作用对象包括装备授予技能，公告未限定为施法武器。固定目录三种技能项链是互斥候选，完成 v102 唯一技能解析后，可以按已登记规则接入单技能辅助孔。对当前目录非变体、以规范 Grants Skill 行表示的固定技能作枚举，没有同时含两行以上固定授予技能的普通基底；这一结果不证明游戏不存在多技能装备，也不用于扩大传奇制作范围。

实现复用既有孔声明与结果，通过独立资格读取器支持三种项链，不修改完美溶剂的施法武器资格。目标仍是辅助孔数量；共同负容量行与授予技能等级不变。稳定目标槽位不依赖原文行序，孔数未知不默认为二孔，旧版项目不能夹带新孔声明、目标或未执行动作。中文起点原文、孔声明及实际材料消费独立保存。

本轮 Exa 检索发现有第三方攻略仍称工匠石必须逐档使用，与官方 0.2.0 的直接设孔示例冲突，不采用其规则、价格或期望费用。实际读取 CoE 公共更新日志的手动改孔说明，没有足够信息区分装备符文孔与技能辅助孔，不把该说明当作辅助孔机制实测。本轮没有把用户真实样本交给外站，没有复制同行数据。

多技能同时操作时的混合孔数覆盖、真实客户端辅助孔复制格式和 Sanctified 例外仍待证据。此处完成的是对明确单技能项链的规则接入与应用验证，不能替代真机验收。

## 已确认的版本差异

| 机制 | 可追溯结论 | 对实现的约束 |
| --- | --- | --- |
| 工匠石设定孔数 | [GGG 0.2.0，Item Changes](https://www.pathofexile.com/forum/view-thread/3740562/filter-account-type/staff)改为直接设定辅助孔，明确举例从二孔用完美材料到五孔 | 不沿用旧版逐级增加一孔的前置要求，不自动计入较低档材料费用 |
| 装备授予技能 | [GGG 0.5.0，Item Changes](https://www.pathofexile.com/forum/view-thread/3932540)允许三档工匠石作用于授予技能的装备，并作用于该装备的全部技能 | 辅助孔与装备符文孔分开；多技能不能默认只处理第一项 |
| 圣化数值 | 同一 0.5.0 公告明确改为按当前属性值相乘 | 不能先按词缀范围重掷，再缩放；不能照搬旧攻略的神圣重掷顺序 |
| 圣化后特殊镶嵌 | [GGG 0.5.4，General Changes and Improvements](https://www.pathofexile.com/forum/view-thread/3975218/filter-account-type/staff)禁止向腐化／Sanctified 装备新镶所列九种特殊材料 | 限制新镶操作，不据此删除已有镶嵌物，也不泛化为所有普通符文一律禁止 |

0.5.0 公告使用的是 **Sanctifying**。搜索不到名词 Sanctification 不能据此断言公告没有相关规则；本次已直接核对正文。未发现官方公告给出这里需要的完整随机分布与取整公式。

## 辅助孔：可以进入设计的部分

[Lesser](https://poe2db.tw/us/Lesser_Jewellers_Orb) 与 [Greater](https://poe2db.tw/us/Greater_Jewellers_Orb) 的公开物品说明经 Exa 检索核对：分别设为三孔、四孔，要求当前少于目标孔数。完美材料的五孔结果由上述 0.2.0 官方示例确认。[Perfect 页面](https://poe2db.tw/us/Perfect_Jewellers_Orb)本轮正文提取只有元数据，不能将其当作已读完整工具提示。页面的 DropLevel 不是承载装备或技能的使用等级门槛。

代码现状：`grantedSkills.ts` 按基底行索引识别授予技能；`perfectFlux.ts` 管理装备技能最高等级。`CraftState.grantedSkillLevel` 表达完美溶剂的等级效果，现有 `sockets` 属于符文孔。两者均不能冒充辅助孔数量；现有高级文本未提供辅助孔时，也不能从 `S S`、技能等级或角色等级推断。

接入顺序：

1. 明确起点的辅助孔声明与来源，缺失保持未知；按已识别技能关联，避免新增一个无法处理多技能的总孔数字段。
2. 优先支持单个已识别、非传奇装备技能。核对可辅助资格、当前孔数和材料规则后，增加独立步骤；多技能孔数不同时的覆盖与拒绝规则另行查证，不能只凭“全部技能”推导降低已有高孔数。
3. 使用现有预览、应用、撤销重做及实际消费计价。再次使用相同或更低档材料的拒绝行为要有回归测试，不从目标孔数反算材料消耗。
4. 接入目标、条件指引、步骤清单和完整项目历史。旧格式检查起点、未来步骤、未执行策略及报价，不能静默丢掉辅助孔声明。

需要继续核对：装备各类授予技能是否均可辅助、腐化／Sanctified 状态资格、辅助孔是否随装备或角色保存、多技能混合孔数，以及三服原生复制格式。普通技能宝石制作和传奇装备修改不因这次调研扩大范围。

## 圣化：先明确状态，再实现数值变化

[PoE2 Wiki 的预兆条目](https://www.poe2wiki.net/wiki/Omen_of_Sanctification)检索结果提出每组独立的 0.78–1.22 倍、步长 0.01 和向上取整说法。本轮没有取得完整可核验的实验或官方公式；仅作 gray 待追溯线索，不据此建立执行公式、等概率选择或期望费用。

以下问题不能由“按当前数值相乘”独立推出：

- 固有、显式、破裂、工艺、亵渎及不可缩放属性分别是否参与。
- 同组多行与伤害两端是否共用倍率；负数、小数及技能等级如何取整。
- 催化品质、侧别增效、Destruction 增效与圣化的计算顺序，是否保存原基础值。
- 原生高级文本中的状态行、倍率头、范围和基础值表示；国服译名不能用人工翻译代替已验证输入语法。
- 后续普通镶嵌、萃取及其他例外能否执行。官方列举的特殊镶嵌限制不是全部操作矩阵。

现有 `ItemDocument` 和 `CraftState` 没有独立 Sanctified 状态。实现应先覆盖原文识别、状态展示、导入资格和项目回放，再接入可证明的数值操作；不能仅增加一个按钮或沿用 `corrupted` 布尔值。尚未识别的文本仍走现有未知内容路径，本轮未复现并确认“已有圣化装备可被制作”的缺陷，不将缺少字段直接报告成漏洞。

收尾提示应显示仍未完成的技能等级、辅助孔与其他已配置目标，由同一状态验证决定步骤是否可执行。具体例外未核实前，不能用“以后无法任何修改”替代逐项规则。圣化与腐化两种操作也不能共享未经证明的数值模型。

## 下一实施节点与验收

优先补齐装备技能辅助孔的起点及资格证据，再接入独立操作；圣化的状态与数值规则分阶段推进，不把不确定倍率写进现有核心。沿用单一操作执行器和历史消费派生，避免 UI、路线与回放各写一套规则。

| 验收方向 | 最小覆盖 |
| --- | --- |
| 孔位隔离 | 增加辅助孔不改符文孔、孔内物或技能最高等级 |
| 不完整信息 | 未知辅助孔不当二孔；无授予技能或身份不明确不生成步骤 |
| 直接设孔 | 从较低孔数到目标值，不强制消费中间档材料 |
| 多技能 | 先明确支持范围；不忽略其他技能或悄悄降低已有孔数 |
| 历史 | 撤销重做、保存恢复、未来操作与旧格式拒绝保持一致 |
| 收尾状态 | 不能通过修改声明、复用其他状态标记或重开项目绕过资格 |
